# Deployment Guide

How to build and deploy **balajichippada.com** (Firebase Hosting + Cloud
Functions). Written so another agent/operator can reproduce a deploy exactly.

---

## TL;DR (hosting — the common case)

```bash
# 1. Build (transforms .jsx -> .build.js and regenerates roadmap.html)
npm run build

# 2. Bump the ?v= cache-bust query for EVERY changed asset in BOTH
#    index.html AND roadmap.html (see "Cache-busting" below)

# 3. Deploy the working tree (see full script under "Deploy hosting")

# 4. Verify the live version
curl -s -H "Cache-Control: no-cache" \
  "https://balajichippada.com/?cb=$(date +%s%N)" \
  | grep -oE "(app\.build\.js|styles\.css)\?v=[0-9]+"
```

The deploy uploads **whatever is on disk** in the working tree. So build and
bump versions *before* deploying — there is no build step inside the deploy.

---

## Why not `firebase deploy` / `firebase-tools`

`firebase-tools` **rejects the service-account credential** in this environment
("Failed to authenticate") and interactive `firebase login` sessions expire. So
we deploy by calling the **Firebase Hosting / Cloud Functions REST APIs
directly**, authenticating with a service-account key via `firebase-admin`.

This is the whole reason the deploy is a hand-rolled script instead of one CLI
command.

## Step 1 — Build

```bash
npm run build      # = build:js (esbuild transform) + prerender
npm test           # optional: 33 offline unit tests (pretest re-runs build)
```

- `app.jsx  -> app.build.js` and `v2.jsx -> v2.build.js` (esbuild **transform**,
  not a bundle — top-level functions become `window` globals; `v2.build.js` must
  load before `app.build.js`).
- Prerender regenerates `roadmap.html` from the `index.html` template + `data.js`.
  **Do not hand-edit `roadmap.html`** — it is generated; edit `index.html` +
  `data.js` and rebuild.
- Static pages (`about.html`, `guides/*.html`) are **not** regenerated by the build.

Confirm the build is fresh before deploying:

```bash
[ ! app.jsx -nt app.build.js ] && echo "app OK" || echo "app STALE — run build"
[ ! v2.jsx  -nt v2.build.js  ] && echo "v2 OK"  || echo "v2 STALE — run build"
```

## Step 2 — Cache-busting (mandatory)

Browsers/CDN cache by URL. For every asset whose **content changed**, bump its
`?v=N` query string in **both** `index.html` and `roadmap.html`. If you skip
this, users keep the old cached file even after a successful deploy.

Assets that carry a `?v=`: `app.build.js`, `v2.build.js`, `styles.css`,
`data.js`, `site.config.js`, `videos.js`, `firebase.config.js`, `seo.config.js`.

```bash
# example: bump app.build.js from 42 -> 43 in both files
for f in index.html roadmap.html; do
  perl -i -pe 's/app\.build\.js\?v=42/app.build.js?v=43/' "$f"
done

# sanity: the two files must agree on every version
diff <(grep -oE "\?v=[0-9]+" index.html) <(grep -oE "\?v=[0-9]+" roadmap.html) \
  && echo MATCH || echo MISMATCH
```

## Step 3 — Deploy hosting

The script is written into `functions/` (for `firebase-admin` resolution), run,
then deleted. It clones the live version's `config` (headers/rewrites), gzips +
hashes every file, uploads only the hashes Hosting says it's missing, finalizes,
and releases.

```bash
cd "<repo root>"
cat > functions/_deploy_hosting.js <<'EOF'
const admin=require('firebase-admin');const fs=require('fs'),path=require('path'),zlib=require('zlib'),crypto=require('crypto');
const sa=require(process.env.KEY);admin.initializeApp({credential:admin.credential.cert(sa)});
const SITE=sa.project_id,ROOT=path.resolve(__dirname,'..'),API='https://firebasehosting.googleapis.com/v1beta1';
function ig(rel){const s=rel.split('/');if(['firebase.json','package.json','package-lock.json','PAYMENTS-TODO.md','Prompt.md'].includes(rel))return true;if(s.some(x=>x.startsWith('.')))return true;if(s.includes('node_modules'))return true;if(rel.startsWith('scripts/'))return true;if(rel.startsWith('tests/'))return true;if(rel.endsWith('.jsx'))return true;if(rel.endsWith('.md'))return true;if(rel.startsWith('functions/'))return true;const b=s[s.length-1];if(b==='serviceAccountKey.json'||/firebase-adminsdk/.test(b))return true;return false;}
function walk(d,o=[]){for(const n of fs.readdirSync(d)){const a=path.join(d,n),r=path.relative(ROOT,a).split(path.sep).join('/');if(ig(r))continue;const st=fs.statSync(a);if(st.isDirectory())walk(a,o);else if(st.isFile())o.push(r);}return o;}
async function tk(){return (await admin.credential.cert(sa).getAccessToken()).access_token;}
async function api(m,u,b,t,raw){const h={authorization:'Bearer '+t};let p=b;if(raw)h['content-type']='application/octet-stream';else if(b!==undefined){h['content-type']='application/json';p=JSON.stringify(b);}const r=await fetch(u,{method:m,headers:h,body:p});const x=await r.text();if(!r.ok)throw new Error(m+' '+r.status+' '+x.slice(0,200));return x?JSON.parse(x):{};}
(async()=>{const t=await tk();const rel=await api('GET',`${API}/sites/${SITE}/releases?pageSize=1`,undefined,t);const cur=rel.releases?.[0]?.version?.name;const config=(cur?await api('GET',`${API}/${cur}`,undefined,t):{}).config||{};const files=walk(ROOT),man={},gz={};for(const f of files){const g=zlib.gzipSync(fs.readFileSync(path.join(ROOT,f)),{level:9});const hh=crypto.createHash('sha256').update(g).digest('hex');man['/'+f]=hh;gz[hh]=g;}const v=await api('POST',`${API}/sites/${SITE}/versions`,{config},t);const pop=await api('POST',`${API}/${v.name}:populateFiles`,{files:man},t);const need=pop.uploadRequiredHashes||[];console.log('files',files.length,'uploading',need.length);for(const h of need)await api('POST',`${pop.uploadUrl}/${h}`,gz[h],t,true);await api('PATCH',`${API}/${v.name}?update_mask=status`,{status:'FINALIZED'},t);await api('POST',`${API}/sites/${SITE}/releases?versionName=${encodeURIComponent(v.name)}`,{},t);console.log('✅ Released');})().catch(e=>{console.error('❌',e.message);process.exit(1);});
EOF
cd functions && KEY="/Users/gowtamsingulur/Downloads/balaji-chippada-agentic-ai-firebase-adminsdk-fbsvc-66c9cae699.json" node _deploy_hosting.js
rm -f _deploy_hosting.js
```

**What gets uploaded:** the `ig()` ignore filter mirrors `firebase.json`'s
`hosting.ignore` — it excludes `node_modules`, dotfiles, `functions/`, `tests/`,
`scripts/`, `*.jsx`, `*.md`, service-account keys, and build metadata. Keep
`ig()` in sync with `firebase.json` if either changes. Expected output is a file
count (~36) and a small "uploading N" (only changed files).

## Step 4 — Verify

CDN edge propagation lags a few seconds; always verify with a cache-busting
query so you're not reading your own browser/edge cache.

```bash
sleep 4
curl -s -H "Cache-Control: no-cache" "https://balajichippada.com/?cb=$(date +%s%N)" \
  | grep -oE "(app\.build\.js|styles\.css|data\.js)\?v=[0-9]+"
```

The printed versions must match what you bumped in Step 2. Tell the user to
hard-refresh (Cmd/Ctrl+Shift+R) if they still see an old bundle.

## Deploying Cloud Functions

Same REST pattern, different API (`cloudfunctions.googleapis.com`). Only needed
when `functions/index.js` (or `functions/lib/*`, `functions/package.json`)
changed — **skip it for pure frontend deploys.**

Procedure:
1. `generateUploadUrl` → upload a zip of `index.js`, `package.json`,
   `package-lock.json`, `lib/`, and `skill-mentor-reply/` (gen1, nodejs20).
   Omitting `skill-mentor-reply/` doesn't crash the deploy, but
   `generateEnquiryReply` then refuses every request — its prompt lives in
   those markdown files.
2. Create or `PATCH` the function with the new source. `_deploy_fns.js`
   PATCHes the existing `TARGETS`; `_deploy_new_fn.js` creates a brand-new
   function (clones runtime + env vars from `sendBulkEmail`, sets IAM).
3. For `onCall`/HTTPS functions, `setIamPolicy` granting `allUsers` the
   `roles/cloudfunctions.invoker` role.
4. Clone env vars from the existing function so config isn't lost.

Requires the **Cloud Functions Admin** + **Service Account User** roles (see
Prerequisites). The Hosting rewrite for `/api/youtube-playlist` points at the
`getYouTubePlaylist` function — a functions change there won't show until the
function is redeployed.

## Gotchas & rules

- **Deploy = the on-disk working tree.** Build + bump versions first; the deploy
  does neither.
- **Never hand-edit `roadmap.html`** — regenerate via `npm run build`.
- **Bump `?v=` in BOTH `index.html` and `roadmap.html`**, or the change won't
  reach cached users.
- **Never commit the service-account key** (gitignored as `*-firebase-adminsdk-*.json`).
- **Never write test data to production Firestore docs** while debugging.
- **Falsy-zero:** `0` is a valid price (free masterclass) — never gate on `!price`.
- **Firestore `orderBy('createdAt')`** silently drops docs missing that field —
  sort client-side instead.
- **CDN lag is normal** — verify with a cache-busting query, not a plain reload.
- Deploying does **not** commit or push. Commit + push are separate, explicit
  steps.
